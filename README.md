# ارتقای دستیار گفت‌وگومحور – Sirjan Carpet AI

## ساختار
فایل پیوست‌شده پروژه Vite نبود؛ یک HTML تک‌فایلی بود (React و Babel از CDN). برای همین سایت همان‌طور حفظ شد و یک بک‌اند کوچک **بدون وابستگی** (فقط Node ≥ 20.12) کنار آن اضافه شد.

```
sirjan-carpet.html            سایت (فقط بخش دستیار و چند متن «نمایشی» تغییر کرده)
sirjan-carpet.original.html   نسخه اصلی برای مقایسه/بازگشت
server/index.js               سرور: صفحه سایت + /api/chat + /api/health، محدودیت مصرف، اعتبارسنجی
server/providers.js           اتصال به مدل (Anthropic یا هر سرویس سازگار با OpenAI)
server/prompt.js              ساخت پرامپت سیستم از اطلاعات واقعی سایت
server/knowledge.json         محصولات/رنگ‌ها/متن‌ها؛ خودکار از HTML استخراج می‌شود
scripts/extract-knowledge.mjs بازسازی knowledge.json     (npm run knowledge)
scripts/test-server.mjs       آزمون بک‌اند با مدل آزمایشی محلی   (npm test)
.env.example                  نمونه تنظیمات
```

## راه‌اندازی
1. Node.js 20.12 یا بالاتر.
2. `cp .env.example .env` و سه مقدار `LLM_PROVIDER`، `LLM_API_KEY`، `LLM_MODEL` را پر کنید (جدول زیر).
3. `npm start` و باز کردن `http://localhost:8787`.
4. تا وقتی کلید تنظیم نشده باشد، صفحه دستیار به‌روشنی می‌گوید «تنظیم نشده» و ارسال پیام غیرفعال است.

> سایت را مستقیم با دوبار کلیک روی HTML باز نکنید؛ دستیار فقط وقتی کار می‌کند که از آدرس سرور باز شود. اگر سایت روی دامنه دیگری است، قبل از اسکریپت اصلی `window.SIRJAN_API_BASE='https://api.example.com'` را تنظیم و `ALLOWED_ORIGINS` را در سرور پر کنید.

## انتخاب ارائه‌دهنده (تصمیم با شماست)
| گزینه | LLM_PROVIDER | LLM_MODEL | LLM_BASE_URL |
|---|---|---|---|
| Anthropic (Claude) | `anthropic` | شناسه مدل از کنسول Anthropic | پیش‌فرض |
| OpenAI | `openai` | شناسه مدل از OpenAI | پیش‌فرض |
| سرویس سازگار با OpenAI (OpenRouter، سرویس‌های داخلی/میزبانی‌شده، مدل محلی) | `openai` | شناسه مدل همان سرویس | آدرس `/v1` همان سرویس |

کلید فقط در `.env` یا متغیرهای محیطی سرور قرار می‌گیرد؛ هیچ‌جای HTML/مرورگر نیست و نام متغیرها با `VITE_` شروع نمی‌شود. `.env` را در گیت نگذارید.

## رفتار دستیار
- پاسخ‌ها از مدل زبانی واقعی می‌آیند؛ پرامپت سیستم از داده‌های واقعی سایت ساخته می‌شود (۱۸ محصول، رنگ‌ها، متن شیریکی‌پیچ، هنرمندان، دکور، تماس).
- قیمت همه محصولات و اندازه ۷ محصول در سایت «ثبت‌نشده» است؛ دستیار موظف است همین را بگوید و حدس نزند. موجودی، ارسال، بازگشت کالا، ایمیل و آدرس فروشگاه هم در سایت نیست.
- دکمه‌های «درخواست خرید/مشاوره» سایت فعلاً نمونه‌اند؛ دستیار سفارش ثبت نمی‌کند و به شماره‌های سایت ارجاع می‌دهد.
- تاریخچه: مرورگر آخرین ۲۰ پیام را با هر درخواست می‌فرستد؛ مکالمه با رفتن به صفحه دیگر، تغییر زبان و بازخوانی همان تب حفظ می‌شود (sessionStorage) و دکمه «گفت‌وگوی تازه» دارد. سرور چیزی ذخیره یا لاگ نمی‌کند.
- زبان پاسخ از زبان آخرین پیام کاربر تعیین می‌شود (فارسی/انگلیسی)؛ زبان سایت فقط پیش‌فرض است.
- کدهای محصول در پاسخ (مثل SP-112) لینک صفحه همان محصول می‌شوند.
- خطاها: نبودن تنظیمات، قطع اتصال، تایم‌اوت، شلوغی/محدودیت ارائه‌دهنده، محدودیت مصرف خود سرور (۱۰ پیام در دقیقه و ۱۵۰ در روز برای هر IP، ۳۰۰۰ در روز کل؛ قابل تنظیم)، پیام خیلی طولانی؛ هر کدام پیام فارسی/انگلیسی و دکمه «تلاش دوباره» دارند.

## نکته‌ها
- پشت reverse proxy (Nginx، Cloudflare) مقدار `TRUST_PROXY=1` بگذارید، وگرنه محدودیت مصرف بر اساس IP پروکسی حساب می‌شود.
- محدودیت مصرف در حافظه است؛ برای چند نمونه سرور باید به Redis منتقل شود.
- اگر محصول/متن سایت را عوض کردید: `npm run knowledge` و سرور را دوباره اجرا کنید.
- `/api/design` عمداً `501` برمی‌گرداند (تولید تصویر در این مرحله پیاده نشده). `/api/health` همچنان `configured:false` می‌دهد تا صفحه طراح هوشمند خود را «آماده» نشان ندهد؛ وضعیت دستیار در `chat.configured` است.
